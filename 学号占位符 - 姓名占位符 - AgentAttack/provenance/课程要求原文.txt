                    2026 软件安全课程项目
                       智能体安全攻防与评估

1. 项目内容与基本要求
    本课程项目围绕智能体安全攻防与评估展开。你需要面向真实或合理的智能体使用场景，设
计并实现智能体攻击模式及相应的攻击实例，在受控环境中验证其是否能够对现有 Agent 产生可
观察的安全影响，并对不同 Agent / 模型上的效果进行比较和分析。

l   作业可 1 人独立完成，也可 2–3 人组队完成。
l   每人至少探索并实现 1 种攻击模式，并围绕该模式构造至少 3 个以上攻击实例。（如 3 人组
    队，则应完成 3 种不同的攻击模式）。
l   攻击模式，是指攻击者利用某类可控输入、内容或组件，通过相对稳定的核心攻击机制或执
    行路径影响 Agent，并产生某类安全影响的一种可复用攻击方式；攻击实例则是该攻击模式
    在具体用户场景中的实际实现。
l   同一攻击模式下的不同实例应在正常使用场景、攻击者可控内容或组件、攻击触发条件、攻
    击执行路径、目标资源或安全影响等方面具有实质差异。
l   攻击必须有合理的用户场景和攻击者能力假设，并产生明确、可验证的攻击结果或安全影
    响，例如数据窃取、控制劫持、非预期操作、资源滥用等。注意：避免只停留在“理论上可能”
    的描述。
l   应在不同 Agent / 模型或配置上进行测试，观察攻击是否成功以及效果差异。最终样例应至少
    在一种受测环境中体现出可验证的安全影响。

2. 选题方向与攻击样例
选题不限，以下方向仅供参考，也可以自行设计其他智能体攻击方式。以下内容是选题方向，不
等同于具体攻击模式，同一方向下可以探索多种不同的攻击模式。但需要能够说明：正常使用场
景（用户原本想让 Agent 做什么）、攻击者能够控制什么、攻击通过什么机制影响 Agent，以及
攻击成功后会造成什么安全后果。
l   恶意 Skill 与 Skill 操纵：构造表面上能够完成正常用户任务、但包含额外攻击行为的 Skill，
    或者通过 Skill 的描述、指令、脚本等影响 Agent 对 Skill 的选择、任务规划和实际执行。例
    如在完成正常任务的同时读取额外文件、访问测试凭据、执行非预期工具调用，或者诱导
    Agent 选择攻击者指定的 Skill。
l   不可信外部内容与间接提示注入：在 Agent 会读取或处理的网页、文档、邮件、工具返回内
    容、GUI 界面等外部内容中嵌入攻击指令，使原本应作为“数据”处理的内容反过来影响 Agent
    的决策和执行。例如改变原有任务、诱导额外工具调用、读取非必要数据或执行其他非预期
    操作。
l   记忆与持久状态污染：利用具有记忆、历史记录或自动学习能力的 Agent，使攻击内容被保
    存并在后续任务中再次发挥作用。例如让恶意信息进入长期记忆、经验记录或自动生成的
    Skill，使一次攻击能够持续影响之后的任务、工具选择或执行过程。
l   资源劫持与非预期资源使用：诱导 Agent 使用其能够访问的计算、API、账号、通信、存储或
    其他资源去执行并非用户任务所需要的操作。例如产生大量非必要调用、消耗额外计算/API
    配额、代表用户发送非预期请求，或者使 Agent 的资源被用于攻击者或第三方的其他目的。
l   跨组件与供应链攻击：通过多个 Skill、工具、依赖、外部服务或多个 Agent 之间的调用关系
    传播恶意行为。例如，正常 Skill 引入存在攻击行为的依赖或外部组件，某个工具或服务返回
    的恶意内容进一步影响后续 Agent，或者多个单独看似正常的组件组合后产生危险行为。恶
    意 MCP Server、恶意工具或外部服务也可以作为这类攻击的具体实现方式。
l   其他智能体安全问题：只要攻击场景合理、影响可验证，并与 Agent 的决策、工具使用、权
    限、记忆或执行过程直接相关，均可作为选题。
l   注意 1：单纯的模型回答错误或幻觉不能直接作为攻击样例；仅针对普通聊天模型进行
    jailbreak、且不涉及 Agent 的任务执行、工具调用、权限或决策过程的攻击，也不属于本项
    目重点。项目中应存在明确的攻击者控制面，即攻击者能够实际控制或构造的输入、内容或
    组件，并能够解释它如何导致相应的安全影响。
l   注意 2：仅修改文件名、变量名、Prompt 措辞、目标地址等表面参数，不视为新的攻击实
    例；同一攻击在不同 Agent / 模型或配置上的测试，以及重复运行，均属于该实例的实验记
    录，不单独计为新的攻击实例。例如，多个恶意 Skill 均利用正常文件访问能力额外读取与任
    务无关的敏感数据，可以属于同一种攻击模式；仅将 secret.txt 替换为 token.txt 不算新的实
    例，而核心机制改为通过 Skill 描述操纵 Agent 优先选择该 Skill，则属于另一种攻击模式。


3. 实验要求
    实验的重点是证明“攻击确实有效”，而不是只展示一段恶意代码或提示词。建议按照以下过程
完成：
(1) 针对每种攻击模式确定正常用户场景和威胁模型，说明攻击者可以控制的内容、攻击成立的
    前提、核心攻击机制以及攻击目标。
(2) 针对每个攻击实例构造攻击版本，并准备一个正常/对照版本。两者应尽量只在攻击机制上存
    在差异，以便判断安全影响是否确实由攻击造成。
(3) 在不同 Agent / 模型或配置上运行并记录结果。至少保留关键输入、Agent 的主要行为、工具
    调用或终端日志，以及能够证明攻击成功或失败的证据。若结果具有明显随机性，应进行多
    次运行并报告成功情况。
(4) 比较不同模型或配置中的结果，分析攻击为什么成功或失败，并整理成他人可以按照说明重
    新运行的最小可复现实例。
    实验安全及伦理规范：严格遵守信息安全、网络安全相关法律法规、遵循实验伦理，不对他
人计算机设备、网络造成负面影响。所有测试必须在授权、隔离、可恢复的环境中进行，不得影
响外部服务、他人账号或他人设备。实验中涉及的 token、密码、文档和隐私信息应使用虚构或测
试数据；涉及“数据外传”时使用 localhost、mock server 或其他测试接收端模拟，不得向真实第三
方发送敏感数据。不得进行未经授权的公网扫描、攻击或破坏性操作。

4. 提交要求
l    Agent 安全攻击实验报告
     每组最终提交“实验报告 + 可复现攻击模式及实例”。按照以下结构整理压缩包：
     [学号-姓名-AgentAttack]/
     ├── report.pdf # 实验报告
     ├── README.md # 总体环境与复现说明
     └── patterns/
     ├── pattern_01/
     │ ├── pattern_info.json # 攻击模式基本信息
     │ ├── instance_01/
     │ │ ├── sample_info.json # 攻击实例基本信息
     │ │ ├── attack/ # 实际测试的攻击版本
     │ │ ├── control/ # 正常/对照版本
     │ │ └── evidence/ # 关键⽇志、结果与截图
     │ ├── instance_02/
     │ └── instance_03/
     └── pattern_02/ # 组队时的其他攻击模式

     其中，README 需要说明运行环境、安装/配置方式、执行步骤以及复现入口。每个 pattern
目录下的 pattern_info.json 用于描述攻击模式，至少记录：模式名称/编号、所属选题方向、攻击
面、攻击者可控内容或组件、核心攻击机制、预期安全影响以及所包含的实例编号。每个
instance 目录下的 sample_info.json 用于描述具体攻击实例，至少记录：实例名称/编号、所属攻
击模式、正常用户场景、具体攻击输入或组件、攻击前提、攻击成功判据、测试的 Agent/模型、
结果摘要以及证据位置。
     实验报告包括：(1) 背景与用户场景；(2) 威胁模型、攻击模式与实例设计；(3) 实验环境与测
试方法；(4) 实验结果与原因分析；(5) 安全影响、局限性和复现说明。报告中的结论应能够由提
交的日志或实验结果直接支持。
